Module-root indexing and queries

The root-level uir commands index Go modules. A module path from go.mod is the stable root key; a canonical filesystem path is a location of that root, not its identity. Two clones or worktrees declaring the same module path share a root but have independent location heads. The first registered location remains the primary location, and uir query reads its head by default.

uir add .
uir list
uir get example.org/service
uir reindex .
uir dependencies --snapshot 6f8b2c6e-79af-4b59-8736-e45696f0c546
uir query 'service.Run =' --root example.org/service
uir query 'service.Run <' --root example.org/service --location ../service-feature
uir query 'service.Run =' --snapshot 6f8b2c6e-79af-4b59-8736-e45696f0c546

uir add [path] defaults to . and indexes immediately. Discovery follows these rules:

  • A directory scan finds every visible go.mod beneath it, including nested modules without a separate .git marker.
  • A package directory selects its nearest enclosing go.mod and scans the whole module. Nested modules' files are excluded from their parent module's scan.
  • In a Git checkout, discovery includes tracked and non-ignored untracked files, respecting nested .gitignore rules and repository excludes. Outside Git, it scans the filesystem.
  • A nested location records its nearest parent and mount path; .gitmodules provenance marks a declared submodule.
  • Symlinked input paths are canonicalized, but discovery does not traverse directory symlinks.

add indexes only the selected directory; add --all also adds the use paths of an enclosing go.work that lie outside it, and fails on a missing or invalid use path. A module below a go.work that does not use it is loaded on its own, with GOWORK=off, as the Go toolchain requires. uir reindex [path] accepts only previously registered module locations and uses the same extractor. uir reindex --all indexes only registered Go checkouts without heads, in parent-first order, and skips external roots, which only their producer refreshes; it does not accept a path or --force and stops on an unavailable or failed checkout. --include-tests includes _test.go files; --force re-extracts every file, fails if a stored document differs from the fresh extraction under the same indexer version, and publishes a new snapshot even when the content is unchanged.

Each new snapshot records the root's go.mod requirements, including indirect ones, their declared replacements and Go-selected versions, and the exact target snapshot when one can be resolved. Indexing a requirement through a local go.work module or directory replacement also registers and indexes that target, including during reindex; the workspace flags above still control bulk addition of unrelated go.work use modules. Local dependency cycles publish their member snapshots and cross-links together, and a changed member causes a new linked set. A versioned target is indexed from a matching tag or pseudo-version commit in an already registered local checkout; cycles among registered tagged versions likewise publish their snapshots and links together without moving checkout heads. UIR does not fetch Git remotes. Missing selected versions, tags, or checkouts leave an explicit unresolved edge. Historical commits use standalone module resolution and ignore current workspaces and local directory replacements; failed package loading retains parseable source with syntax coverage and dependency diagnostics.

Every snapshot records coverage_deterministic: whether extracting the same commit, configuration and dependency set again must reach the same coverage. It is true when the whole go/packages load ran and every error of every package it loaded, dependencies included, is a parse or type error, or a list error proving an import absent from the commit's pinned, already fetched module versions or the toolchain's standard library (import lookup disabled by -mod=readonly, no required module provides package, is not in std, and the like), and every dependency edge is resolved or unresolved for a reason module selection or version registration decides. A whole-load failure, an unknown error, an unrecognised list error, any error naming a network, proxy, checksum-database, module-cache or file-system failure, and an edge whose module selection failed or whose local directory could not be resolved are not deterministic: classification fails closed. A list error of any loaded package that names one of those infrastructure failures (for example one module download failing with dial tcp, a proxy 502 Bad Gateway, a checksum mismatch or permission denied) fails the index with an error naming the package and the message, and publishes nothing: a transient failure is never cached as coverage. An unknown or unrecognised error without such text still publishes, marked not deterministic. Rows published before the column existed are null and count as not deterministic; nothing backfills them. A snapshot's coverage is settled when it is complete (indexed or excluded) or degraded and marked deterministic; that one rule decides both the historical and the versioned-dependency reuse below. A historical commit whose stored clean snapshot under the same configuration and dependency set hash has settled coverage is reused without type-checking, and a versioned dependency whose stored snapshot has settled coverage and a complete closure is linked without checking its version out. Otherwise the commit is extracted, and a stored snapshot identical to the extraction (context hash, coverage and coverage determinism) is reused instead of publishing a duplicate, so re-extracting a commit whose only snapshot predates the column publishes a classified one. The reuse-check phase counts why the early check missed, from the closest stored snapshot of the commit: miss-none (no clean snapshot of the commit), miss-configuration, miss-dependency-set, or miss-coverage (degraded and not known to be deterministic); sibling-recorded counts a snapshot that read a workspace sibling. A reused revision reports the stored snapshot's file count as both its files and its reused files. The no-extract probe uir diff --auto-index runs before starting an index task makes the same early check over the same dependency set: it links each versioned dependency to its stored version snapshot by the rule above, without checking out, indexing or publishing anything, so an indexed commit whose dependencies are all stored is reused without a task. A version that indexing would have to index first (none stored, a moved tag, an unsettled coverage or an incomplete closure) makes the dependency set differ, and the probe misses.

Dirty Git-backed snapshots use git-{full commit}-dirty-{latest UTC file mtime} as their revision, including when a linked local dependency makes an otherwise clean parent dirty. git_commit separately records the raw commit. Older snapshots remain readable but report dependencies as not captured until reindexed. The Explorer Dependencies pane opens linked target snapshots directly, including historical snapshots; dirty source bytes are stored so later local edits do not change what those snapshots show.

The CLI selects a nonempty --dsn, then UIR_DSN, then SQLite at ~/.config/uir/uir.db, creating the default directory if needed. Existing databases at other paths are not moved. Plain .db paths, sqlite:// URLs, and PostgreSQL DSNs are supported. See the CLI configuration reference for schema and profiling options. The database owner is storage.UirDB; its embedded HCL is applied to the selected target before queries or indexing.

Module API

uir serve exposes the root-level operations as structured JSON at GET /api/v1/modules, GET /api/v1/modules/by-key/{root}, POST /api/v1/modules/add, POST /api/v1/modules/reindex, POST /api/v1/modules/import (below), and POST /api/v1/modules/query. GET /api/v1/modules/locations?root=... lists registered checkouts; GET /api/v1/modules/snapshots?root=...&location=... pages through one checkout's immutable snapshots. GET /api/v1/modules/browse?snapshot=... returns effective sources and the node projections read from their documents; GET /api/v1/modules/content?snapshot=...&path=... returns hash-verified source bytes; GET /api/v1/modules/dependencies?snapshot=... returns declared dependency edges and linked target snapshots. URL-encode full module paths and checkout paths in request parameters. Positional CLI arguments are the JSON args array; flags are JSON fields, for example {"args":["service.Run <"],"root":"example.org/service"} for a query. HTTP add takes the same all field to include an enclosing go.work's external uses. These operations use Clicky's typed result path, so HTTP clients receive data rows rather than captured terminal tables. Indexing operations appear as module-index runs at GET /api/v1/tasks and in the browser's Tasks view. The browser's Cmd+K palette searches module roots plus files and symbols in the selected snapshot.

GET /api/v1/modules/heads returns a plain JSON array of each indexed checkout's current head and effective source files without symbol payloads. Symbol and typed-selector suggestions are also plain arrays; these routes do not wrap results in {items, warnings}. Registered checkouts without a head are skipped and reported by uir status (GET /api/v1/modules/status) and the Overview dashboard. The Explorer Files pane groups those heads by module, adding checkout rows when a module has multiple locations, then by source folder. Selecting a file switches the active module, checkout, and snapshot together. File and folder rows use bundled VS Code icons. See browser and API for response shapes and asynchronous index runs.

The sidebar's System details dropdown shows the frontend build version, backend binary version, and live database type, version, location, and size. GET /api/v1/system/info provides the backend and database fields without exposing connection credentials. SQLite size is the live page count multiplied by page size; PostgreSQL size is pg_database_size(current_database()). make build VERSION=... and make install VERSION=... embed the same version in the frontend and backend.

Storage hierarchy

ModuleRoot (go.mod module path)
├── ModulePrimary ── primary ModuleLocation
├── ModuleLocation (canonical checkout path, parent location and mount)
│   └── ModuleLocationHead ── latest published ModuleSnapshot for that checkout
└── ModuleSnapshot (immutable, optional base snapshot)
    ├── SourceDelta (set revision or delete path)
    │   └── SourceRevision (path, content hash, and package)
    │       └── Document (content-addressed typed or syntax facts for that revision)
    ├── DocumentDelta (set document ordinal or delete path)
    ├── PackageCoverage (package input hash, export shape, and coverage diagnostics)
    ├── SnapshotDependency (go.mod requirement and optional target ModuleSnapshot)
    └── SymbolDelta (set or delete of one defined symbol, with public, private, and content fingerprints)

Symbol (canonical id, global; database-local handle numbered through SymbolModule and SymbolPackage)
└── SymbolPosting (document ordinal, role, occurrence count)

modules.root_key is the full module path; name is its basename. locations uses (root_id, canonical_path) as its unique physical identity. A location head is scoped by root and location, references a snapshot of that same location, and carries a monotonically increasing version. The primary row is set once, when the first location is registered; adding a second location does not redirect default queries.

Each new location bases its first snapshot on the current primary head, if one exists. A later run at the same location bases on that location's previous head, including after a branch switch. A run publishes a child snapshot unless its revision, content-set hash, configuration hash, context hash, and resolved dependency set all equal the base snapshot's; --force always publishes. The content set is the included .go files plus the dependency manifests: the module's go.mod and go.sum under their module-relative paths, and the go.work and go.work.sum of the enclosing workspace, wherever it sits, under the fixed keys go.work and go.work.sum. The manifests enter only the hash; they are never stored as source revisions. A dependency bump with unchanged Go source therefore publishes zero source deltas, while documents are reused wherever their extracted facts still match. The configuration hash covers the indexer version, test inclusion, and the build variant that go env, run in the module directory, reports for the toolchain: GOOS, GOARCH, CGO_ENABLED, GOVERSION, GOFLAGS, and an empty explicit build-tag list for normal indexing. A new variant changes the configuration and requires fresh extraction; if go env fails, indexing fails. The context hash digests every package input hash, so a different context with identical bytes also publishes. Changes to other non-Go files that do not change the Git revision are outside the snapshot trigger.

A snapshot stores only changed path operations. set points to a SourceRevision keyed by root, path, content hash, package path, and any explicit Git binding. delete is a tombstone and has no revision ID. Unchanged content reuses a revision row across locations and snapshots. The extracted facts live in a document keyed by root, path, and a digest of its source revision, package, indexer version, coverage, and canonical JSON. A package input hash decides whether extraction is needed; it covers configuration, package path, source hashes, and direct imports' export shapes. Re-extracting a package does not duplicate documents whose rendering is unchanged.

A package that type-checks under go/packages gets typed documents (indexed, or partial when it has type errors) with proven canonical symbol ids and symbol_postings. A package that cannot be type-checked retains syntax declarations and call locators without canonical ids or postings. A file whose own document fails is published with syntax facts or an empty document and a warning; see coverage. Each snapshot records package_coverage, its context_hash, and document bindings as document_deltas. It also records symbol_deltas: changes to its defined-symbol set and layered fingerprints, computed from changed packages. EffectiveSources, ActiveDocuments, and EffectiveSymbols reconstruct their respective views from the base chain; queries do not assume every snapshot physically contains every source, document, or symbol row.

Discovery, hashing, and type-checked extraction finish before the publication transaction opens; revision, symbol, document, dependency edge, and posting writes happen inside it, as does the allocation of new symbols' handles and new documents' and the snapshot's ordinals. On PostgreSQL a publication that loses an allocation race to a concurrent writer is retried from the start, at most three times. Modules published together share that transaction: a database or invariant failure rolls back its root, location, revision, document, snapshot, and head writes. Dependencies published in earlier calls remain available. A snapshot row is written only in the transaction, after its documents, and together with its deltas and package coverage, before its location head is advanced; there is no building or failed snapshot state. Each snapshot records worktree_state: clean when its Git sources and dependency inputs match the commit, dirty when either changes, and unknown with an empty revision outside Git. Existing heads use a version-checked update; a concurrent writer changing the version makes publication fail instead of silently overwriting it. Additional go.work paths selected by uir add --all are separate indexing requests, so a later request's failure does not roll back an earlier successful publication.

Query scope and call references

The compact PEG grammar accepts a qualified symbol followed by <, >, =, <<n, :impl, :inherits, :methods, :uses, or ~w; filters, set operators, and bounded >> call paths compose these operations. :uses lists resolved symbols that a declaration's own body reads, writes, or calls. See the query guide. --root selects a module path, --location selects one registered checkout, and --snapshot selects one historical immutable snapshot. --location and --snapshot cannot be combined. Without an explicit location or snapshot, queries read the primary head of each selected root. On the command line inside a registered checkout, an empty --root and --location default to that checkout; --all selects every registered root instead.

The symbol operations resolve a spelling to canonical symbols and read the postings of those symbols in each selected snapshot's active documents. One identity declared at several heads is one target whose declarations are listed separately; if a spelling matches several identities in scope, the command returns candidate rows with their full query name, root, checkout, source position, and snapshot instead of choosing one arbitrarily. Select --location, --snapshot, or a full import path to disambiguate. Every result lists the packages in scope that are partial, syntax, or excluded, because those hold no or only some proven facts.

The extractor type-checks each package with go/packages under the recorded build variant and records only what the type checker proves; a package that cannot be type-checked falls back to syntax coverage from the AST extractor, and a file that build constraints exclude gets an excluded document. It skips hidden, underscore-prefixed, vendor, and testdata directories and excludes tests unless requested. A long chain of tiny snapshots keeps writes small but makes effective-view reads traverse more ancestors; compaction and retention are not implemented. PostgreSQL is appropriate for shared writers; SQLite remains a local single-process store.

Publishing from a non-Go producer

A producer that is not the Go extractor, such as one lowering business rules from XML, publishes a symbol set it built itself, and uir query then answers over it exactly as over a Go module. uir import reads one publication, a JSON file or - for stdin, and publishes it; POST /api/v1/modules/import does the same with the publication object as the body's publication field. Go callers use indexer.Publish(ctx, db, publication). The docs example is two roots, Co/Prod and Co/Prod/PlanA, of rule, screen, and record sources; a spec keeps it equal to the fixture the publication specs run (UIR_UPDATE_EXAMPLES=1 go test ./indexer regenerates it):

uir import docs/examples/import/co-prod.json
uir import - < docs/examples/import/co-prod-plana.json
uir query 'kind:test.rule'
uir query 'field:Policy.Amount < mod:Co/Prod/PlanA'
uir query 'records.Policy.Amount ~w'
uir query 'func:Apply >'
FieldMeaning
root_keyThe root's identity, as a Go module path is one: any non-empty string.
nameThe root's display name when the publication registers it.
location.uriWhere the producer read the root from. It is stored as the location's canonical path with location kind external.
revisionThe producer's revision of its sources, such as a commit; may be empty.
kindsCustom kinds the publication uses, {name, category, metrics?}, registered as storage.RegisterKind does (a namespaced name and one of container, type, callable, member). Optional metric declarations describe non-negative integer symbol.metrics.<name> fields; see producer metrics.
symbolsThe identity of every symbol the documents name, declared or referenced, owners included: module_key, package_path, kind, owner_id, name, parameter_types, and visibility.
documentsPer source: path_key (a relative slash path), package_path, source (the text), content_hash (its lowercase hex SHA-256), and content, the typed document of its facts (current format 12). Optional git_path binds original source to a repository file.

Every declared symbol in a document's content carries the layered hashes a Go symbol does (hashes and identities), and validation refuses a symbol without them: content_hash (64 hex, the implementation; required on every symbol), and, on every symbol with an id, public_shape and public_hash (what a consumer outside the symbol's visibility boundary observes) and private_hash (the full declared structure, digesting public_hash, so a public change is always a private change). shape stays the private shape text. The package's export shape digests its exported symbols' public_hash, so a private-only change re-keys no importer.

A document carries only canonical ids, and an id's module, package, kind, owner, and parameter types cannot be recovered from it, so a publication lists the identities beside the documents. Everything else comes from the documents, as for Go: definitions from their declarations, references from every occurrence with a symbol, call edges from call occurrences with a target and a statement path, writes from write occurrences. A producer computes each id with indexer.SymbolID(indexer.Identity{ModuleKey, PackagePath, Kind, OwnerID, Name, ParameterTypes}), the function Go extraction uses, so a symbol published by two roots, or by Go and a producer, is one id. A document declares only symbols of its own root and package: a selector matches a symbol only in the root its module_key names, and symbol deltas group declarations by package. A symbol of another root that a document references, such as a field of Co/Prod read by a Co/Prod/PlanA rule, is listed in the referencing publication's symbols as well.

Publication shares the Go publication core (indexer/publication.go). Publish validates the whole publication before writing anything, against the database's kinds plus the kinds it declares: required fields, paths, hashes, kinds, owners, every document through storage.DecodeDocument (so an enclosing id must be declared in the same document), and every named id against symbols. A failure names the root and the document or symbol, wraps indexer.ErrInvalidPublication (a 400 invalid_publication over HTTP), and leaves the database untouched, declared kinds included. Publish then registers the declared kinds and hands the core the same extraction IndexModules builds for a Go module, which, in one transaction, registers the root and its external location, compares the publication with the location's head, and otherwise publishes an import snapshot: source revisions, documents and postings, source and document deltas, package coverage, symbol deltas against the head, stats, and a compare-and-swap head update. Content-addressed documents are reused by (root, path, content digest) even when their package input hash changes. A publication whose revision, sources, and documents all equal the head's publishes nothing and reports unchanged. Snapshots record worktree state unknown; generated sources use stored blobs, while original sources can use explicit Git bindings. See Git-backed publication for repository bindings, historical deltas, and verified source reads.

A root is either Go or external: publishing into a root indexed from a Go checkout, or adding a Go checkout whose module path is an external root's key, fails. Only the producer refreshes an external root: uir add and uir reindex given its URI or root key fail saying it is published by an external producer, and uir reindex --all skips it even when the handle cutover left it without a head; republish it with uir import.

Publishing UIR nodes

A producer that already holds its root as UIR nodes, such as a database catalogue lowered into uir.RecordTable and uir.MethodNode values, does not build documents by hand: indexer.PublicationFromNodes(indexer.NodePublication{RootKey, Name, Location, Revision, Options, Documents: []indexer.NodeDocument{{PathKey, PackagePath, Nodes}}}) returns the Publication to hand to indexer.Publish, so there is no second publication path.

  • Symbols. Every node and every member is a declared symbol: a table's columns, indexes, foreign keys, and triggers, a record's fields, and a class's or interface's variables, constructor, destructor, methods, and nested types. Its kind comes from its node type (table, column, index, foreign_key, record, field, type for a class, interface, endpoint, constructor, and func or method for a callable without or with an owner; a view is a table). Any other node type is an error. A package node is not a symbol: the document is the package.
  • Classes. A uir.TypedNode class is the builtin type kind, whose type_form validation checks against the form its shape classifies as (storage.ClassifyTypeShape). The shape is the one source of that form, in either shape language a type has: a Go indexer shape is a Go type declaration, classified with go/parser, and a class's uir.Shape opens with class and is struct, since UIR models no alias or defined non-struct type (a UIR interface is the interface kind, which has no type form). PublicationFromNodes fills type_form from the same function, and a shape that is neither is an error, so no Go parse is attempted on a UIR shape and no producer-supplied form can disagree with it. type_form is what a struct: selector filters type symbols by.
  • Identity. module_key is the root key, package_path the document's, owner_id the owner's id (a column is owned by its table, so two tables' id columns are two symbols), name the identifier's name, and parameter_types a callable's parameters, each its SQLType, else its field type, else its type reference, so overloads differ. Build tables with uir.NewTable, which stamps each member with its table, and give a class's members its package and Type in their identifiers; two symbols with one id or one identifier key are an error, as is a node without a name.
  • Visibility. Indexes, foreign keys, and triggers are private members, so they are internal; any other symbol is exported when its UIR visibility is public or unset and its owner is exported, else internal.
  • Layers. public_hash, private_hash, and content_hash are uir.Fingerprint's layers, public_shape and shape are uir.Shape's public and private text, payload is uir.MarshalNode, and semantic_hash is Hash(). A node with no implementation anywhere beneath it has an empty content layer, which is published as the SHA-256 of uir-node-content-none-v1, so every symbol has a 64-hex content_hash and two bodiless declarations compare equal.
  • Source. The source is always generated, never supplied, so its spans cannot disagree with its symbols: per top-level node, its private shape with each symbol's name after its kind and each member's line, the line uir.MemberLine says the shape embeds it as, expanded in place to the member's own text (table customers sql:table {, column id bigint (int) not null identity pk, primary key (id), }). A symbol's lowered body — a function's, method's, or trigger's Body, and a view's Definition — follows its last member line, before its closing brace, as the plain text of the body's Pretty() rendering indented under the symbol ( method orders_audit () event=insert timing=after, audit_log()). The same nodes always produce the same bytes, every symbol's extent nests inside its owner's, and a changed column or index changes only its own line and an edited body only lines inside its symbol's extent, so a line diff of two revisions' stored sources attributes each changed line to the symbol whose extent holds it, and uir diff --stat counts body edits on the symbol that owns them.

Legacy cutover

The earlier uir project ... command, project browser API, and project GORM tables are removed. Opening an existing database discards those old tables after applying the module schema; it does not backfill project snapshots. Back up the database before opening it with this version if that history is needed. See storage design for the exact table allowlist and dependency checks.

A database indexed before compact symbol handles is recognised on open by modules lacking its ordinal column. Before migration, in one transaction, its index (snapshots, heads, source revisions and deltas, documents, symbols, postings, and package coverage) is discarded, while the registered roots, locations, and primary locations are kept and the roots are numbered. Run uir reindex --all to rebuild registered headless checkouts; opening the database logs a warning saying so. Until then uir list and uir get show the root with an empty snapshot id and head version 0. Unscoped queries and readers skip missing heads, which uir status lists, while an explicit root or checkout selection without a head fails. A read-only open refuses such a database.

The same applies, by the same mechanism, to a database whose symbol deltas still carry the two-layer shape_fp and body_fp fingerprints (documents of format 4, with shape_hash and body_hash): its index is discarded on open, its registrations are kept with their ordinals, and uir reindex rebuilds it with the public, private, and content layers.
