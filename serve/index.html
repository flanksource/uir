Browser and API

Opening an older database can discard legacy project history or indexed snapshots. Back it up before opening it with this version; the storage cutover instructions describe affected layouts and reindexing.

Build and serve UIR against a local SQLite database or PostgreSQL:

pnpm --dir web install
make build
mkdir -p state
go run ./cmd/uir --dsn ./state/uir.db serve --host localhost --port 8080

--host defaults to localhost and --port to 8080. The database is migrated and checked before the listener opens. The command serves embedded Vite assets and Clicky operations on one origin. For live frontend development, use go run ./cmd/uir --dsn ./state/uir.db serve --dev; the command starts the Vite server and proxies its UI while API requests remain on the same origin. Dev mode and frontend tests use @flanksource/clicky-ui source from the sibling clicky-ui/packages/ui/src directory when it exists, or from CLICKY_UI_ROOT/packages/ui/src when configured. That checkout needs its own dependencies installed. When the source directory is absent, they use the installed package. Production builds always use the pinned package. Dev mode requires the local web/node_modules/.bin/vite executable.

The browser lists module roots, their registered checkout locations, and immutable snapshots. The scope picker in the top-right of the header defaults to "All modules"; choosing a root scopes the browser to that root's primary checkout head. Select a checkout to inspect effective sources and node projections; source content is displayed only after its bytes match the indexed content hash. The Query tab runs compact queries and SQL navigation against the selected scope: with "All modules", clicky.StartTask < reads the primary head of every indexed root and returns recorded callers with their Root column. Add indexes a directory or package path, discovering enclosing and nested Go modules; Reindex refreshes a registered location. The URL retains module, location, snapshot, source, node, the revealed line and column, search, expression, and offset so a view can be reopened.

The browser uses these Clicky routes:

Method and routePurpose
GET /api/v1/modules and GET /api/v1/modules/by-key/{root}Root list and detail.
GET /api/v1/modules/headsPlain array of indexed checkout heads and their effective files; headless checkouts are skipped.
GET /api/v1/modules/statusIndex coverage and registered checkouts without heads.
GET /api/v1/modules/locations?root=...Registered checkouts for one root.
GET /api/v1/modules/snapshots?root=...&location=...Paged snapshots for one checkout.
GET /api/v1/modules/browse?snapshot=...Effective sources and node/call projections for one snapshot.
GET /api/v1/modules/content?snapshot=...&path=...Hash-verified bytes for one module-relative source.
GET /api/v1/modules/dependencies?snapshot=...Declared go.mod requirements, selected versions, linked target snapshots, and unresolved reasons.
POST /api/v1/modules/querySQL or compact query with args containing the expression and optional language (auto, compact, sql), root, location, snapshot, and limit fields. Omitting scope fields reads primary heads across indexed roots. Compact results use the query envelope; SQL results use columns, rows, total, coverage, and optional graph or path. X-Total-Count reports total.
GET /api/v1/modules/query-catalogSQL fields, functions, domains, and relationships used for completion.
GET /api/v1/modules/graph?selector=...Call graph around one function or method, selected by selector (a symbol expression) or symbol (a canonical symbol id), with optional direction (callees, callers, both), depth (1 through 8), limit (1 through 1000), exclude (a comma list of package patterns, std,builtin,gorm.io/... when absent, none for nothing), root, location, and snapshot query parameters. Returns roots, nodes, edges, groups, and omitted beside the effective exclude patterns, the packages reached, stages, and candidates; an ambiguous selector returns its candidates with an empty graph. A pattern that is not an import path, a /... pattern or a keyword is a 400 invalid_query.
GET /api/v1/modules/suggest and GET /api/v1/modules/suggest-selectorsPlain arrays of active symbol objects or typed-selector strings for prefix, with optional root, location, snapshot, and limit query parameters.
POST /api/v1/modules/diffCommit-to-commit symbol diff with args containing <from>..<to> and root, visibility, change-type, stat, auto-index, include-tests, snapshot-from, and snapshot-to as JSON fields.
POST /api/v1/modules/add and POST /api/v1/modules/reindexStart an index run for a new directory or registered location. Returns 202 Accepted with {"run_id":"..."}; follow the run through GET /api/v1/tasks and the Tasks view.
POST /api/v1/modules/importPublish a non-Go producer's root with the publication object as the body's publication field. Answers synchronously with the ModuleResult (root_key, location, snapshot_id, head_version, files, parsed_files, reused_files, unchanged); a publication refused before anything is written is a 400 invalid_publication.
POST /api/v1/modules/refactor/preview and POST /api/v1/modules/refactor/applyPreview a gopatch rename or move, then apply the reviewed diff.

URL-encode module paths, checkout paths, and source paths in requests. /api/openapi.json describes the generated API, including the connection routes below. The removed /api/v1/project, /api/v1/snapshot, /api/v1/root, /api/v1/source, and /api/v1/node routes are not compatibility aliases.

The heads, suggestion, SQL connection, and connection-database lists return JSON arrays directly, without an items or warnings wrapper. Snapshot listing remains paginated, and query results retain their compact or SQL envelope. Use the status route for missing-head diagnostics.

For example, run a SQL metric query over one registered root:

curl -sS http://localhost:8080/api/v1/modules/query -H 'Content-Type: application/json' -d '{"args":["SELECT symbol.name, symbol.metrics.param_count FROM func:* WHERE symbol.metrics.param_count > 3"],"root":"example.org/service"}'

The content route first verifies that the requested path belongs to the selected snapshot and cannot escape its module location. If the current local file has the saved SHA-256 hash, it returns those bytes. Otherwise, dirty and non-Git snapshots read their stored source blob; clean snapshots can read the pinned Git blob. An imported snapshot uses its stored blobs or explicit Git source bindings; its producer URI is not treated as a checkout. Every source is hash-verified. If no source matches, the route returns an error instead of displaying current bytes as historical content. No remote repository is fetched automatically by the default reader.

Explorer Rename and Move require a current, fully indexed local checkout and a gopatch executable. serve --gopatch-bin defaults to the Go bin directory; set it to an absolute path when gopatch is installed elsewhere. Symbol renames pass this server's UIR DSN to gopatch, which checks current indexed references in the module and its consumers. Preview sends snapshot, source, optional node, action, and either new-name or module-relative destination; Apply sends the same fields plus preview-hash. Apply rejects a changed diff, then reindexes affected registered checkouts. The preview includes changes to workspace and configured consumer modules. The refactor routes accept only local, same-origin requests.

Connections and database captures

Open /connections on the local server to save and test connections. UIR serves the commons-db connection service, the same one the commons-db query app uses, so every connection type its form schema offers can be saved, and secret references such as op:// are accepted. Stored passwords and certificates are never returned by the API, and leaving one blank while editing preserves its stored value.

For a local SQLite source, create a saved connection through the browser or the API:

curl -sS -X POST http://localhost:8080/api/v1/connection -H 'Content-Type: application/json' -d '{"name":"Local catalogue","type":"sqlite","url":".tmp/catalog.db"}'

Test the saved connection, then choose it in Add a database. PostgreSQL, SQL Server, MySQL, and SQLite connections can back database modules; Git, hosted source control, and S3 connections can be saved and tested. Adding a database module takes its first read-only schema capture. Capture schema takes later captures manually. Captures store catalogue metadata, not table rows. A same-module comparison covers every schema; a cross-module comparison requires one schema from each capture and matches objects by exact name and SQL type. MySQL currently contributes relation and column names and types; comparisons involving MySQL omit metadata that its inspector does not capture.

The local, same-origin API provides the commons-db connection routes: GET/POST /api/v1/connection, GET/PUT/DELETE /api/v1/connection/{id}, POST /api/v1/connection/test and POST /api/v1/connection/resolve (both act on an unsaved draft), GET /api/v1/connections/dashboard, and GET /api/v1/connections/health. GET /api/v1/connection with Accept: application/schema+json supplies the connection form schema. With Accept: application/json and ?types=postgres,mysql,sql_server,sqlite, it returns a plain array of saved SQL connections. A connection that a database module uses cannot be deleted until the module is removed; the database's foreign key enforces this. POST /api/v1/database-modules/connections/{id}/databases returns a plain array of database names the saved SQL connection can reach. GET/POST /api/v1/database-modules, POST /api/v1/database-modules/{id}/capture, GET /api/v1/database-modules/{id}/snapshots, and POST /api/v1/database-modules/diff manage captures and comparisons. The OpenAPI document lists these routes and their request and response shapes.
