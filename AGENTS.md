# uir — agent notes

Shared ways of working, the gavel todo workflow, and global skills come from the root `~/.agents/AGENTS.md`.

## What this repo is

The canonical UIR model, extracted from `arch-unit/models/uir`. `arch-unit` still carries its own copy; nothing imports this module yet. Rewiring arch-unit's 89 importing files onto `github.com/flanksource/uir` is a separate, deliberate follow-up that needs this module published first.

## Layout rules

- `Pretty()` and `Hash()` are part of the `Node` interface, so their implementations are locked to the package that declares the node types. Rendering and hashing cannot move to subpackages; only consumers of `Node` can.
- `diff/` and `render/` are the two things that legitimately live outside the root package — both only consume `Node`, neither is imported by it. Keep it that way; a new subpackage is only viable if the root package never needs to reference it.
- `graph/` builds a bounded nodes-and-edges call graph from any `graph.Source`. It imports only the root package, the standard library, `flanksource/commons` and clicky's rendering API (`clicky/api`, for `Pretty`), so it stays language-neutral: `graph.FromRelationships` serves the relationships `uir.CollectRelationships` finds in a lowered method body, and an index-backed source belongs beside the index, not in `graph/`. The statement walker (`walk_stmt.go`) and `CollectRelationships` stay in the root package beside `hash_stmt.go`, because a new statement type must be taught to both in the same change; `WalkStatements` panics on a type it has no case for, and a registry spec walks every `uir.Statements` entry to prove it.
- `lower/` is the scaffolding a non-Go lowering shares to record the references a body makes: `lower.Recorder` (offset dedupe, the guard stack as `[]uir.ConditionStmt`, offset→line resolution into `uir.UIRRelationship`s with `Kind`/`Via`/`Content`, and `PositionError`) and `lower.DecodeAt`, the offset-keeping `encoding/xml` element decode. It imports only the root package and the standard library. What a reference is, which elements carry one and how a condition is built stay with the language's lowering.
- `golang/` lowers Go syntax (`go/ast`) into UIR expressions: `golang.LowerExpr` structures what UIR models and keeps every other expression as its exact source text. It imports only the root package and the standard library and reads syntax alone, never types. The index-backed `graph.Source` and the call-site guards built on it live beside the index, in `query/graph_source.go` and `query/graph_guards.go`.
- `themes.go` is the single home of the style class strings and the icon and colour tables rendering uses. A `Style*` name is a role, not a colour: two roles that share a class stay two names, so restyling one does not restyle the other. Render with a theme name, never an inline class string; `render/`, `symboldiff/` and `cmd/uir` use the exported names where the role matches exactly.
- `NodesOf[T Node]` in `nodes.go` is the single widening helper. Do not reintroduce per-type `nodesFromX` converters.
- `schema/uir.schema.json` is generated by `make schema` (`cmd/genschema` over `internal/schemagen`) and must never be hand-edited. `internal/schemagen` is the third package outside the root, and like `diff/` and `render/` it only consumes the root package. It derives the node and statement unions from the `uir.Nodes` and `uir.Statements` registries and the enums from the package's typed string constants, so registering a type or adding a constant is the whole change — there is no list to update. The same command writes `python/statement_kinds.py` (the registered statement kinds and cross-hierarchy refinements the Python encoder checks refinements against), so it too is generated, never hand-edited.

## Deliberate exclusions

These were left in arch-unit on purpose — do not "restore" them:

- `cel_test_helpers.go` (`EvalAssertions`, `AddAssertionIndex`). Keeping it would make `gomplate/v3` and `cel-go` compile-time dependencies of every consumer, for two functions.
- `python/extractor.go` and `python/extractors/`. Extractor tooling, not model; its `init()` wrote to `$HOME/.arch-unit`.
- `json_polymorphic.go` (`PolymorphicRegistry`). Dead duplicate of `registry.go`; nothing referenced it.

The Python model is pure stdlib — it has no `requirements.txt` or `Pipfile` by design. `sqlglot` and `pex` were extractor dependencies.

## Verification

`make build`, `make lint` (must be 0 issues) and `go test ./...` are the gates. A model change that is not followed by `make schema` fails `TestSchemaIsUpToDate`; the same package also checks that the schema accepts what the model actually marshals, which is the part reflection alone cannot guarantee given `MarshalStatement` and `BlockStmt.MarshalJSON` write keys no struct field declares. The Python port is covered by `cross_language_test.go`, which shells out to `python3 python/test_uir.py` and unmarshals the result into the Go types — so a change to either side that breaks the shared JSON shape fails the Go suite.

The `java/` tree is source only, with no build file, exactly as it was in arch-unit. It is not compiled by CI.
